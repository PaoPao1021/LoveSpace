# LoveSpace 产品与工程审计（2026-08）

## 产品结论

项目原本的问题不是功能不足，而是 20 多个功能入口权重接近、首页缺少明确的日常主任务，同时存在贴纸、毛玻璃、奶油色与旧高饱和粉色并存的视觉割裂。

本轮将产品主线收敛为：

1. 每天用一个问题建立连接。
2. 用心情和共同记录承接当下。
3. 用月报看见长期关系变化。
4. 其他工具服务于共同生活，而不是争夺首页注意力。
5. 健康目标比较各自的过去，奖励双方坚持，不建立体重排名。

## 竞品启发

| 产品 | 核心做法 | LoveSpace 的取舍 |
|---|---|---|
| Paired | 每日问题、双方回答后解锁、关系主题内容 | 采用“先各自回答、双方完成后揭晓”，不引入付费内容体系 |
| SumOne | 每日问题与共同养成形成稳定回访 | 采用每日仪式与关系能量，但不复制虚拟宠物和重游戏化 |
| Between | 私密双人空间、回忆、日历与重要日期 | 保留相册、时间轴、纪念日，并把私密访问校验放到服务端 |
| 恋爱记 | 极简记录、沉浸式时间轴、情绪色彩 | 收敛首页视觉和入口层级，保留原生小程序的轻量优势 |

## 本轮落地

### 体验

- 重构首页信息层级，移除无主线的随机情话与重装饰粒子。
- 新增每日问答页面，并在首页显示双方回答进度。
- 新增关系月报，汇总问答、心情、回忆和积分。
- 重构自定义 TabBar 与个人页分组。
- 全项目迁移统一主色、背景色和文字对比。
- 登录与主要提交按钮补充真实加载和禁用状态。
- 修复感谢墙新增后不刷新、列表永远为空的问题。
- 修复设置页修改昵称不落库、背景只保存临时路径的问题。
- 新增“一起变好”第一版：个人健康目标、每日打卡、双人周进度、挑战积分与健康周报。

### 数据与安全

- 修复启动时覆盖 `globalData` 导致首页误判未绑定的问题。
- 使用登录云函数返回的用户资料作为启动唯一数据源。
- 移除小程序前端对云数据库的直接读写。
- 修复每日问答乱码及错误的 `user1/user2` 情侣字段。
- 修复月报错误的 `toUserId/points` 积分字段。
- 相册、纪念日、点滴、愿望、胶囊、菜单、任务、积分、通知均增加情侣空间归属校验。
- “仅自己”心情不再出现在伴侣列表、日历和今日心情接口中。
- 积分兑换改为服务端校验项目价格和余额，阻止负数兑换或伪造价格。
- 菜单订单校验每个菜品是否属于当前情侣空间。
- 积分余额增加服务端快照；加减分、兑换、任务奖励与余额更新使用同一事务。
- 点单、积分兑换、任务完成与定时提醒增加幂等保护，连点或网络重试不再重复写入。
- 创建、加入、解除情侣空间改为事务写入，并为默认相册与纪念日增加可恢复初始化。
- 用户主要文本在服务端通过微信内容安全接口检查，云调用权限随函数配置部署。
- 纪念日提醒按北京时间计算、按天去重，并提供正式定时触发器配置。
- 修复纪念日与点滴更新使用未定义 ID、导致编辑必然失败的问题。
- 健康数据增加情侣成员校验和体重三级隐私；挑战积分使用确定性流水与事务，防止重复奖励。
